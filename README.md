# X-SAGE — eXplainable Situation-Aware Gated Enhancer

Reference implementation of **X-SAGE**, an unsupervised, pluggable, interpretable
situational re-ranking head that augments an arbitrary already-trained
recommender with an *additive, confidence-gated categorical bias*:

```
ŝ(u, i) = s_B(u, i) + κ · γ_S(v) · Σ_k r_k · b̃^(k)_{c(i)}      (Eq. 13)
```

Setting `κ = 0` recovers the backbone exactly (safe fallback). The situational
term is the exact explanation of the adjustment (faithful by construction).

This repository contains **only** what is needed to reproduce the pipeline of the
paper: source code, the processed datasets, the preprocessing scripts, and the
selected hyper-parameters. Trained model artifacts, result tables, and figures
are **not** shipped — they are regenerated by the steps below.

Repository: <https://github.com/knowmis/X-SAGE>

## Repository layout

```
X-SAGE/
├── xsage/                     # the library
│   ├── l0_sensing.py          # L0: causal per-request windows
│   ├── l1_perception.py       # L1: context state (θ) + intent vector (e)
│   ├── l2_comprehension.py    # L2: rough k-means → situations (core/boundary)
│   ├── l3_projection.py       # L3: situation-transition matrix / persistence
│   ├── descriptor.py          # build v = [c̃ ‖ e] end-to-end (per dataset)
│   ├── selection.py           # validation selection of K and ε
│   ├── recommendation.py      # b̃ estimation + additive combiner (Eq. 13)
│   ├── metrics.py             # long-tail groups / exposure helpers
│   ├── data.py                # dataset + backbone-score loaders
│   └── backbones/             # one module per backbone (models + generators)
│       ├── fm.py              #   focal FM (B_full): model, features, scoring
│       ├── deep.py            #   DeepFM and AFM models (context-aware)
│       ├── deepfm_afm.py      #   generate DeepFM / AFM scores   [in-repo, torch]
│       ├── bpr.py             #   generate BPR (B_blind) scores  [Cornac]
│       ├── ease.py            #   generate EASE scores           [Cornac]
│       ├── fpmc.py            #   generate FPMC scores           [Cornac]
│       └── sasrec.py          #   generate SASRec scores         [Cornac]
├── scripts/
│   ├── preprocess/            # raw → processed (per dataset)
│   ├── run_pipeline.py        # X-SAGE head + evaluation → metrics
│   └── aggregate.py           # re-derive metrics from cache (no re-eval)
├── data/processed/            # 5 datasets, ready to use  (~60 MB, included)
├── config/
│   ├── params/<city>.json     # closed perception hyper-parameters (γ, n, β, H, α, depth)
│   └── hparams_<city>.csv      # validation-selected mixing coefficient κ* per backbone/seed
├── requirements.txt
└── README.md
```

## Datasets

Included (processed, per-user chronological 80/10/10 split, 10-core filtered):
**MovieLens-1M**, **Foursquare** (New York, São Paulo), **Yelp**, **KuaiRand-Pure**.
The raw sources are public; `scripts/preprocess/` regenerates `data/processed/`
from a raw dump placed under `data/raw/<dataset>/`.

## Install

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
export PYTHONPATH="$PWD"          # so `import xsage` and the scripts resolve
```

## Reproducing the pipeline from scratch

The head re-ranks the scores of a backbone, so the backbone scores must exist
first. They are large and are **not** shipped; regenerate them per dataset.

```bash
# (0) optional — regenerate processed data from a raw dump under data/raw/
python scripts/preprocess/preprocess_ml1m.py

# (1) train the backbones -> data/<city>/backbone/*.npy  (each backbone is a runnable module)
#     - DeepFM / AFM are trained in-repo (torch); the focal FM is trained inside run_pipeline.py:
python -m xsage.backbones.deepfm_afm ml1m DeepFM
#     - BPR (B_blind), EASE, FPMC, SASRec use the Cornac library; install it in a SEPARATE
#       environment (pip install -r requirements-backbones.txt) and run e.g.:
python -m xsage.backbones.bpr ml1m
python -m xsage.backbones.ease ml1m

# (2) run the situational head + evaluation → outputs/results.csv + cache
python scripts/run_pipeline.py ml1m

# (3) re-derive metrics from the cache after a metric/formula change (seconds)
python scripts/aggregate.py ml1m
```

`config/hparams_<city>.csv` holds the mixing coefficient κ* selected on the
validation split (used at step 2); `config/params/<city>.json` holds the closed
perception hyper-parameters. Both are regenerable from validation and released
here for exact reproduction.

## Notes

- The reported combiner is the additive form of Eq. 13 (`λ = 0`, no long-tail
  term, no selective gate); `κ` is selected per backbone on the validation split.
- Every representation is built only from a user's past (strictly causal intent
  proxy + chronological split), so no request uses information from its own future.
